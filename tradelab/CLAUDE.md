# tradelab: спецификация для Claude Code

## 0. Как работать с этим файлом
- Прочитай файл целиком до первой строки кода.
- Делай строго одну веху за запрос (раздел 12). Следующую не начинай без команды пользователя.
- Не задавай вопросов, кроме блокеров (нет сети, данных, библиотеки). Любую неоднозначность реши сам самым консервативным способом и запиши одной строкой в `DECISIONS.md`.
- Ничего не упрощай молча. Если пункт спецификации невыполним, остановись и напиши, какой и почему.
- Веха закрыта, только когда `pytest -q` зелёный.

## 1. Цель
Ответить на вопрос: есть ли стратегия на ETH, которая после издержек бьёт два эталона (удержание ETH и ETH с таргетом волатильности) по Шарпу и Кальмару вне выборки. Ответ «не найдена» является полноценным результатом.

## 2. Запреты (нарушение = остановка)
1. Никаких ордеров, ключей API, приватных эндпоинтов. Только публичные данные через ccxt.
2. Никаких выдуманных или синтетических данных вместо реальных. Нет данных: стоп и сообщение.
3. Никакого заглядывания вперёд (точная модель исполнения в разделе 5).
4. Holdout читается только функцией `holdout.load(allow=True)`, один раз, на вехе 6.
5. Журнал проб только дописывается: никаких UPDATE и DELETE.
6. `config.yaml` после старта поиска не меняется (контроль хэшем, раздел 9).
7. Цикл «перезапустить, пока не получится» запрещён.

## 5. Модель исполнения и бэктест (единственная реализация)
Индекс: дневные свечи UTC, бар `t` имеет open, high, low, close, quote_volume.
- Стратегия возвращает целевую позицию `s[t]` в [0, max_leverage], используя только данные по close бара `t` включительно.
- Исполнение по open бара `t+1`: `pos[t+1] = s[t]` после применения rebalance_band (позиция меняется, только если отклонение больше band, иначе остаётся прежней).
- Доходность удержания от open до open: `r_oo[k] = open[k+1] / open[k] - 1`.
- Валовая доходность: `g[k] = pos[k] * r_oo[k]`.
- Издержки: `turnover[k] = |pos[k] - pos[k-1]|`; `cost[k] = turnover[k] * (fee + slippage_base + slippage_size_coef * turnover[k] * notional / quote_volume[k])`.
- Фандинг: `fund[k] = max(pos[k] - 1, 0) * funding_day[k]`, где funding_day это сумма ставок за сутки (положительная ставка значит лонг платит). До начала истории фандинга брать `3 * funding_fallback_per_8h`.
- Чистая доходность: `net[k] = g[k] - cost[k] - fund[k]`.
- Сделка: бар с `turnover > 0`.
- В `backtest.py` assert: `pos.max() <= hard_leverage_cap`.

## 6. Метрики (формулы фиксированы)
- Шарп: `mean(net) / std(net, ddof=1) * sqrt(365)`.
- CAGR по кривой капитала `prod(1 + net)`; MaxDD как максимальное падение от пика; Кальмар = `CAGR / |MaxDD|`.
- PSR (Bailey, López de Prado) для дневного неаннуализированного SR: `PSR = Φ((SR - SR0) * sqrt(T - 1) / sqrt(1 - g3*SR + (g4 - 1)/4 * SR^2))`, g3 асимметрия, g4 эксцесс (не избыточный).
- DSR: PSR с `SR0 = sqrt(V) * ((1 - γ) * Φ⁻¹(1 - 1/N) + γ * Φ⁻¹(1 - 1/(N*e)))`, γ = 0.5772, N число проб на реальных данных из журнала, V дисперсия дневных SR всех проб.
- PBO через CSCV: матрица дневных net доходностей всех проб (T × N), S = 16 равных блоков по времени, все C(16,8) разбиений. В каждом: лучшая проба на обучающей половине, её относительный ранг ω на тестовой, `λ = log(ω / (1 - ω))`. PBO = доля λ ≤ 0.
- Разница Шарпов с эталоном: стационарный бутстрэп (`arch.bootstrap.StationaryBootstrap`, средний блок 20), одинаковые индексы для обоих рядов, ДИ уровня ci_level.

## 7. Эталоны (фиксированы, не оптимизируются)
- `bh`: `s[t] = 1`.
- `vt`: `s[t] = min(max_leverage, voltarget_annual / σ[t])`, σ это EWMA (span 30) стандартного отклонения дневных лог доходностей close, умноженное на sqrt(365). Тот же band, издержки, фандинг.

## 8. Пространство стратегий
Позиция = базовый сигнал b[t] в [0, 1], затем слои.

Базовые сигналы (10 штук):
| id | правило |
|---|---|
| don_all, don_no10, don_no160 | Дончиан, окна {10,20,40,80,160} без указанного. Для окна n: вход при `close[t] > max(high[t-n..t-1])`, выход при `close[t] < min(low[t-n//2..t-1])`, иначе держать (ffill). b = среднее по окнам |
| tsmom_20, _60, _120, _250 | `b = 1`, если `close[t] / close[t-L] - 1 > 0`, иначе 0 |
| ma_10_50, ma_20_100, ma_50_200 | `b = 1`, если SMA_fast > SMA_slow, иначе 0 |

Слои:
- Таргет волатильности: нет, или v ∈ {0.10, 0.15, 0.20, 0.25}: `s = b * min(max_leverage, v / σ[t])`. Без слоя `s = b`.
- Фильтр режима: нет, или p ∈ {0.80, 0.90}: если перцентиль σ[t] в расширяющемся окне (минимум 365 дней) больше p, то `s = 0`.
- Фильтр фундинга (гипотеза, заранее записанная в журнал): нет, или q ∈ {0.90}: если перцентиль 7 дневной суммы фундинга в расширяющемся окне больше q, то `s = 0`.

Итого 10 × 5 × 3 × 2 = 300 конфигураций, полный перебор. Каждая конфигурация = одна проба в журнале. Соседи для плато: ±1 шаг по каждой оси внутри семейства (окна, v, p).

Запрещено: шорт, признаки времени суток и дня недели, любые параметры вне сетки.

## 9. Журнал и защита
- SQLite `journal.sqlite`, таблицы `trials(id, ts, config_json, data_range, dataset_sha256, metrics_json)`, `events(id, ts, kind, payload_json)`.
- Проба пишется со статусом `started` до расчёта, метрики дописываются вторым INSERT в `events`, не UPDATE.
- При старте поиска: sha256 от config.yaml пишется в events; каждый следующий запуск сверяет, несовпадение даёт исключение.
- `holdout.load(allow=False)` бросает исключение и пишет событие `holdout_violation`. `allow=True` разрешён один раз: второй вызов тоже нарушение.

## 10. Синтетика
- **A, нулевые данные:** стационарный бутстрэп дневных доходностей ETH до holdout (средний блок 20), 200 путей, из них строятся OHLC (open = предыдущий close, high/low = max/min(open, close) с той же относительной шириной, что в исходном баре). Метрика находки считается относительно `bh` на том же пути.
- **C, слабый сигнал:** A с AR(1): `r'[t] = φ * r'[t-1] + r[t]` для φ из ar_phi_grid.
- **B, реалистичный:** GARCH(1,1) с инновациями Стьюдента (arch), параметры по ETH, плюс пуассоновские скачки: интенсивность и размеры из доходностей ETH за пределами 4σ. Таблица стилизованных фактов реальные против синтетики: эксцесс, индекс Хилла (верхние 5%), автокорреляция |r| на лагах 1, 10, 50, автокорреляция r на лаге 1, корреляция r[t] и |r[t+1]|. Используется только в стрессе.
- **Находка** на любом пути: процедура отбора из раздела 11 выбрала конфигурацию, у которой нижняя граница ДИ разницы Шарпов с `bh` больше 0 и DSR > dsr_min.
- FDR = доля находок на A. Мощность = доля находок на C при каждом φ.

## 11. Конвейер
1. **Подготовка.** Загрузка, проверки, holdout, журнал, хэш config.
2. **Калибровка.** Процедура отбора на 200 путях A и на C. Если FDR > fdr_max: стоп, отчёт, предложение ужесточения, работа не продолжается без решения пользователя. Если мощность при φ = 0.20 меньше 3 × FDR: движок сломан, стоп.
3. **Процедура отбора (walk forward).** Фолды: обучение от начала данных до `test_start - embargo_days`, тест 91 день, первый test_start = начало + min_train_days + embargo_days, фолды до начала holdout. На каждом фолде из 300 конфигураций выбирается одна: максимальный Шарп на обучении среди тех, у кого плато ≥ plateau_min_ratio и сделок в месяц ≤ лимита. Склейка тестов фолдов даёт честную OOS кривую процедуры.
4. **Финальный кандидат.** Та же процедура на всех данных до holdout выбирает одну конфигурацию.
5. **Проверки кандидата.** DSR, PBO, ДИ против обоих эталонов на склеенном OOS, переносимость на корзину (те же параметры, доля монет с net доходностью > 0), стресс: 1000 путей бутстрэпа, двойные издержки, задержка исполнения на 2 бара, соседние параметры, синтетика B. Абляция: каждый слой выключается, слой без улучшения OOS Шарпа удаляется до holdout.
6. **Holdout.** Только если пункт 5 пройден. Один прогон кандидата и обоих эталонов. Если пункт 5 не пройден, holdout не трогать, вердикт «не найдена».

## 12. Вехи и тесты
Каждая веха заканчивается зелёным pytest и отчётом не длиннее 10 строк: что сделано, какие тесты прошли, главный результат, допущения из DECISIONS.md, что нужно от пользователя.

**Веха 1.** config, costs, backtest, metrics, journal, holdout. Тесты:
- Заглядывание: сигналы стратегий до бара t не меняются, если бары после t заменить случайными.
- Издержки: цена константа, позиция 0, 1, 0, 1 каждый бар, band = 0: суммарный net = −n_сделок × (fee + slip) с точностью 1e-12 (slippage_size_coef = 0).
- Плечо: позиция 5 вызывает AssertionError.
- Holdout: чтение без флага даёт исключение и событие в журнале; второе чтение с флагом тоже.
- Журнал: попытка UPDATE или DELETE через API невозможна (методов нет), запись идёт до метрик.
- Config: изменение файла после фиксации хэша даёт исключение.
- DSR: E[max SR] из формулы совпадает со средним максимумом 10000 симуляций N = 100 независимых нормальных SR с точностью 5%.
- PBO: на матрице чистого шума (T = 2000, N = 50) PBO в [0.35, 0.65]; если одна проба имеет добавленный дрейф 0.5 дневной σ, PBO < 0.10.
- Seed: два прогона бэктеста дают побитово равный результат.

**Веха 2.** data.py: загрузка через ccxt с пагинацией, ETH и BTC с самой ранней даты, корзина, фандинг перпетуалов. Проверки: пропуски дней, дубли, |r| > 50% помечаются, всё в UTC, parquet, sha256 в журнал. Если биржа недоступна (ошибка сети или код 451): стоп, попросить CSV со столбцами `timestamp,open,high,low,close,volume,quote_volume`. Отрезать holdout. Отчёт только по эталонам (Шарп, Кальмар, MaxDD, по режимам).

**Веха 3.** strategies, grid (300 конфигураций), walkforward, synth A и C, калибровка (пункт 2 конвейера). Время полной калибровки на ноутбуке до 60 минут (joblib по путям).

**Веха 4.** synth B с таблицей фактов, stress, selection (DSR, PBO, ДИ, абляция, переносимость), финальный кандидат или вердикт «не найдена».

**Веха 5.** report.py: `out/report.md` и png: кривые против эталонов, просадки, таблица по режимам, гистограмма лучшего Шарпа на A с отметкой кандидата, тепловая карта плато, N, DSR, PBO, таблица фактов, ограничения (смещение выживших в корзине, мало режимов, фундинг до его истории взят константой).

**Веха 6.** Holdout по пункту 6 конвейера, допуск по разделу 13, вердикт одной фразой («стратегия, бьющая удержание, найдена» или «не найдена»), список отклонений от этого файла.

## 13. Критерии допуска (все сразу)
- Склеенный OOS: Шарп и Кальмар выше `bh` и `vt`, нижняя граница ДИ разницы Шарпов > 0 против обоих.
- Holdout: Шарп и Кальмар не ниже `bh` и `vt`.
- DSR > dsr_min, PBO < pbo_max, FDR ≤ fdr_max.
- Плато ≥ plateau_min_ratio, переносимость ≥ basket_profitable_share, стресс: Шарп > 0 на ≥ stress_positive_share путей.
- MaxDD ≤ max_drawdown, сделок в месяц ≤ max_trades_per_month.
- Месяц с доходностью > monthly_return_flag: флаг «подозрение на подгонку» в отчёте, не отсев.

Мониторинг распада (CUSUM, полосы Монте Карло) не входит в эту работу.
