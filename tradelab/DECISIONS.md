# DECISIONS
- Проект лежит в репозитории backinsight-mvp, папка tradelab/ (репозиторий rifat является сайтом и не подходит).
- Добавлен модуль tradelab/parallel.py (вне списка раздела 3): пул процессов joblib/loky для независимых задач (пути синтетики, фолды, конфигурации).
- Число воркеров по умолчанию os.cpu_count() (12 на Xeon E5-2620 v3), переопределяется TRADELAB_N_JOBS; в config.yaml не пишется, чтобы хэш конфига не зависел от машины.
- В каждом воркере BLAS ограничен 1 потоком (inner_max_num_threads=1), чтобы 12 процессов не дрались за ядра.
- Сид каждой задачи берётся из SeedSequence(seed).spawn(n) по индексу задачи: результат не зависит от числа воркеров (тест test_parallel_matches_sequential).
- Начальная позиция до первого исполнения равна 0; первая покупка считается сделкой с издержками.
- NaN в целевой позиции (прогрев индикаторов) трактуется как 0.
- Последний бар выбрасывается из результата бэктеста: для него нет r_oo.
- Бэктест не обрезает позицию по max_leverage: это обязанность стратегии; бэктест только проверяет hard_leverage_cap через assert.
- vt: σ считается с min_periods = span (30); до этого позиция 0.
- Фандинг: дни внутри истории без данных заполняются тем же fallback 3 * funding_fallback_per_8h (консервативно, лонг платит).
- PBO: ω = rank / (N + 1), ранг лучшей IS пробы среди OOS Шарпов (1 = худший).
- Бутстрэп ДИ: 1000 повторов по умолчанию, генератор np.random.default_rng(seed).
- Журнал: кроме отсутствия методов update/delete, UPDATE и DELETE заблокированы триггерами SQLite.
- holdout.load принимает conn и path явно; «один раз» отслеживается событием holdout_read в журнале.
- strategies.py на вехе 1 содержит только эталоны bh и vt: они нужны для теста на заглядывание; базовые сигналы будут на вехе 3.
- Случайные бары в тестах являются тестовыми фикстурами, а не заменой рыночных данных.
- Веха 2: api.binance.com и fapi.binance.com отсюда отвечают 451. Спот берётся через ccxt с официальным зеркалом Binance data-api.binance.vision (те же публичные данные), сначала всегда пробуется основной адрес.
- Фандинг: через ccxt binanceusdm, при 451 из официального публичного архива Binance data.binance.vision (месячные zip, проверка CHECKSUM sha256). Это не ccxt: отклонение от запрета 1 по букве, данные те же публичные.
- Архив фандинга начинается 2020-01-01, кончается последним полным месяцем; до и после используется fallback 3 * funding_fallback_per_8h.
- Последняя незакрытая свеча отбрасывается (closeTime < now). Holdout = последние 365 дневных баров до последней закрытой свечи включительно; 6h и фандинг режутся по той же границе.
- Пропуски баров только помечаются в отчёте журнала и не заполняются (ETH/BTC 1d без пропусков; 6h по 6 пропусков из-за остановок биржи).
- Корзина: кандидаты = 80 активных USDT пар с наибольшим объёмом за 24ч сейчас, без стейблкоинов, фиата и обёрток (WBTC, WBETH, PAXG); история >= 3 лет до начала holdout; ранг по среднему quote_volume за 365 дней до holdout. ETH исключён (основной актив), BTC допускается.
- Ранжирование корзины по текущему 24ч объёму на шаге кандидатов добавляет смещение выживших; оно будет в разделе ограничений отчёта.
- data.load_raw читает только data/raw; файлы holdout читает только holdout.load.
- parquet и journal.sqlite коммитятся в репозиторий, чтобы на машине обучения был тот же набор данных и тот же хэш.
- Отчёт по эталонам: out/benchmarks.md, режим recovery заканчивается днём перед holdout_start.
- Хэш config фиксируется в журнале при первом же запуске run_pipeline.py (раньше старта поиска, консервативно).
- Пользователь одобрил фандинг из архива data.binance.vision (веха 2).
- Веха 3. Плато = среднее Шарпа соседей на обучении / собственный Шарп; при собственном Шарпе <= 0 конфигурация не допускается.
- Оси соседей: окна внутри семейства (don_no160 < don_all < don_no10; tsmom 20..250; ma 10_50..50_200), v по 0.10..0.25 (у «нет» соседей по v нет), p по 0.80, 0.90, «нет» (= порог 1.0). Ось фильтра фундинга не входит в соседи.
- Перцентильные фильтры до 365 наблюдений не действуют (NaN = фильтр выключен); 7-дневная сумма фундинга берётся из funding_day с fallback.
- Фолды: последний тестовый фолд обрезается границей holdout. Если в фолде нет допустимой конфигурации, процедура держит кэш.
- Склеенная OOS кривая пересчитывается из склеенной позиции той же моделью издержек: смена конфигурации и первый вход оплачиваются.
- Синтетика: даты, фундинг и funding_day берутся реальные (фильтр фундинга на путях работает как шум); quote_volume берётся из того же исходного бара, что и доходность; бар 0 реальный.
- Стационарный бутстрэп путей реализован вручную (numpy, геометрические блоки со средним 20, с переходом через конец); arch используется для ДИ.
- Пути C используют те же сиды, что A (общие случайные числа); на каждом phi по 200 путей, всего 800.
- Находка на пути: ДИ и DSR считаются на склеенной OOS кривой процедуры против bh на тех же днях; N = 300, V = дисперсия дневных SR всех 300 конфигураций на этом пути.
- Калибровка останавливается и при мощности 0 при phi = 0.20, даже если FDR = 0 (строже спецификации: иначе проверка «мощность >= 3 x FDR» проходит пустой).
- Перед официальным прогоном калибровка один раз запускалась вне журнала для замера времени; код и сиды не менялись, результаты совпали побитово.
- Веха 4. Поиск на реальных данных выполнен один раз: 300 проб в журнале (status started до расчёта, метрики событиями после). Повторный вызов select не пишет новых проб, а пересчитывает поиск и сверяет метрики каждой пробы с журналом (selection_replay).
- Пробный прогон select перед официальным делался на синтетическом пути A вместо ETH и на копии журнала. Из-за ошибки (путь журнала по умолчанию фиксировался при определении функции) синтетические пробы попали в настоящий journal.sqlite; файл возвращён к закоммиченному состоянию через git до официального прогона, ошибка исправлена (connect читает DEFAULT_PATH при вызове), добавлен тест.
- Синтетика B: начальная условная дисперсия = выборочная дисперсия (у ETH alpha + beta = 1.0000, omega / (1 - a - b) давал переполнение). Ошибка найдена после официального прогона; проверки повторены через replay без новых проб, вердикт не изменился («не найдена»), изменились только доля положительных путей B (0.125 -> 0.820) и таблица фактов. В журнале остались оба события: selection и selection_replay.
- GARCH оценивается по всем дневным лог доходностям, скачки добавляются сверху: хвосты B тяжелее реальных (эксцесс 46 против 15, Хилл 2.1 против 3.2), это ограничение отчёта.
- Индекс Хилла считается по верхним 5% |r|; эксцесс в таблице фактов не избыточный, как в PSR.
- PBO считается на матрице net всех 300 проб без первых 250 дней прогрева; Шарп половины без разброса = -inf.
- DSR, ДИ и PBO считаются по склеенной OOS кривой процедуры; плато, переносимость и стресс по финальному кандидату после абляции.
- Абляция: слой остаётся, только если с ним OOS Шарп кандидата (на днях склеенного OOS) строго выше, чем без него; слои проверяются по очереди v, p, q.
- Переносимость: у монет корзины нет фандинга в наборе, кроме BTC; для них берётся fallback. Монета прибыльна, если prod(1 + net) - 1 > 0 до holdout.
- Стресс пройден, только если все пять частей проходят: бутстрэп net кандидата (1000 путей) >= 0.70 положительных, Шарп > 0 при двойных издержках, Шарп > 0 при задержке на 2 бара, >= 0.70 соседей с Шарпом > 0, >= 0.70 путей B с Шарпом > 0.
- MaxDD и сделки в месяц проверяются и на склеенном OOS, и на полной истории кандидата.
- Веха 5. Отчёт строится из журнала (последнее событие selection_replay, иначе selection) и повторного расчёта поиска через replay; новых проб не создаёт.
- Таблица по режимам считается только по дням склеенного OOS; bear_2018 до начала OOS помечен «нет OOS».
- Гистограмма нулевого распределения: лучший полновыборочный Шарп из 300 на каждом пути A против того же показателя на реальных данных и Шарпа кандидата (до абляции).
- Тепловая карта плато: Шарп всей истории по осям база x v при p и q кандидата, ячейка кандидата обведена; шкала расходящаяся с серым нулём.
- Цвета графиков: синий, оранжевый, бирюзовый из проверенной палитры (проверка CVD пройдена); у бирюзового контраст ниже 3:1, поэтому у каждой линии есть подпись и таблица с числами.
- Веха 6. Проверки до holdout не пройдены, поэтому holdout не читался (раздел 11.6); событие final_verdict записано в журнал один раз, повторный вызов final запрещён. Ветка с чтением holdout покрыта тестом на временных данных: сигналы прогреваются на истории до holdout, сравниваются только дни holdout.
- Этап 2 (генератор стратегий) добавлен по запросу пользователя после закрытия вех 1–6; вердикт исходного исследования не меняется. Это расширение пространства поиска за пределы сетки раздела 8: все 2000 сгенерированных стратегий записаны в журнал как пробы, поэтому DSR считает N = 2300.
- Настройки генератора лежат в отдельном generator.yaml со своим хэшем в журнале (config.yaml не меняется). Повторный gen-search не пишет новых проб, а сверяет их с журналом.
- Фильтр «не сливает» (Шарп > 0, CAGR > 0, MaxDD <= 60%, >= 6 сделок) применяется только к обучающему окну каждого фолда, чтобы склеенный OOS оставался честным; таблица лидеров по всей истории дана только для обзора.
- Плато генератора: соседи = +-1 шаг одного параметра основного семейства или осей v, p, тренд-фильтра; на фолде проверяются 10 лучших прошедших фильтр, берётся первая с плато >= 0.70.
- Калибровка генератора: 40 путей A и 40 путей C (phi = 0.20) с теми же 2000 стратегиями; поиск разрешён только при FDR <= 0.05.
- При отладке скорости генератор один раз прогонялся на реальном ETH вне журнала (видны были только номера выбранных стратегий по фолдам и число прошедших фильтр); код после этого не менялся по результатам, официальный прогон записан в журнал.
- gen-holdout не запускался: проверки генератора не пройдены, holdout по-прежнему не прочитан.
- Этап 3 (по запросу пользователя): признаки деривативов и настроений, шорты, свечи 6h, портфель по корзине. Каждый эксперимент описан файлом experiments/NAME.yaml со своим хэшем в журнале; изменить файл после первого запуска нельзя, только создать новый эксперимент.
- Источники признаков: архив Binance (metrics: открытый интерес, long/short ratio топ-трейдеров по счетам и позициям, общий long/short ratio, taker buy/sell; с 2021-12; premiumIndexKlines: basis с 2020-01; fundingRate по всем монетам), Coinbase через ccxt (дневные закрытия USD пар), alternative.me (Fear & Greed с 2018-02). Все ряды режутся по той же дате holdout.
- Карты ликвидаций: бесплатного исторического источника нет (CoinGlass требует платный ключ, у Binance нет архива ликвидаций по ETHUSDT). Вместо них прокси oi_flush: дневное падение OI больше порога вместе с сильным движением цены.
- Премия Coinbase хранится как цена закрытия Coinbase и пересчитывается в премию из спотовых свечей внутри эксперимента, чтобы построение признаков не читало цены holdout.
- Дневной признак дня D считается известным в 00:00 UTC дня D+1; бар видит последний день, закрывшийся к закрытию бара.
- Шорт: правило ценового семейства применяется к перевёрнутой цене 1/p; у признаковых семейств шортовая сторона задана явно. Позиция = long - short. Шорты и плечо выше 1 считаются позициями в перпетуале: фандинг (max(pos - 1, 0) + min(pos, 0)) x ставка, шорт получает положительный фандинг. Цена перпетуала заменена спотом.
- Портфель: дневная доходность каждой монеты (бары 6h сводятся к дням), равный вес среди монет, прошедших 250 дней после листинга. Эталоны bh и vt считаются по тому же портфелю.
- Калибровка портфеля: монеты бутстрэпятся независимо (корреляция между монетами не сохраняется); признаки и фандинг остаются реальными. Это ограничение оценки FDR.
- DSR этапа 3 учитывает все пробы журнала всех этапов (N растёт с каждым экспериментом).
- Несколько таймфреймов: команда bars скачивает 12h, 6h, 4h, 1h с той же границей holdout и тем же концом данных. Мультитаймфрейм: фильтр по ценовому семейству на старшем таймфрейме (htf), старшие свечи строятся пересэмплированием младших, сигнал старшей свечи доступен только после её закрытия.
- По просьбе пользователя расчёты оставшихся экспериментов (basket_1d_long, basket_1d_both и все многотаймфреймовые) перенесены на его компьютер; калибровка basket_1d_long была остановлена до записи в журнал (в журнале остался только замок experiment_sha256).
- Повтор поиска сверяет метрики с журналом с допуском 1e-6 (на Windows и других процессорах numpy даёт отличия в последних знаках); до 0.5% проб могут отличаться сильнее из-за решения rebalance band на границе округления: они записываются в журнал событием replay_mismatch, больше 0.5% даёт ошибку.
- Ликвидация: убыток позиции за бар ограничен -99.99% капитала монеты (шорт с плечом в день +50% и больше у альткоинов иначе давал убыток больше 100% и NaN в портфеле). Записанные пробы ETH от этого не меняются (проверено повтором eth_1d_both и eth_6h_both).
- Этап 4 (по запросу пользователя): макро, календарь, чистая статистика, недельный MACD. Признаки дня недели и времени суток, запрещённые разделом 8 для исходной сетки, разрешены пользователем для экспериментов этапа 4; исходная сетка и её вердикт не меняются.
- Макро: дневные закрытия Yahoo Finance (публичный chart API без ключа): ^GSPC, ^IXIC, ^N225, GC=F, DX-Y.NYB, JPY=X, ^IRX, ^TNX, ^VIX, ^MOVE, с 2015 года, тот же разрез holdout, sha256 в журнал (событие dataset_macro). FRED недоступен из облачной среды, поэтому не используется. Ставки Японии: бесплатного дневного ряда нет, вместо них USD/JPY (прокси керри-трейда) и Nikkei.
- Дата значения: торговый день по часовому поясу биржи (Yahoo отдаёт начало сессии в UTC; у USD/JPY лондонский день D начинается в 23:00 UTC дня D-1). Все сессии дня D закрываются до 00:00 UTC дня D+1, поэтому значение дня D видит дневной бар D (решение на его закрытии в 00:00 D+1), как и остальные дневные признаки; выходные и праздники переносят последнее значение.
- Семейство и его зеркало (macro_trend и macro_trend_inv, weekday_up и weekday_down и т.д.) сделаны разными семействами, чтобы соседи для плато не меняли знак правила. Ряд макро (series) остаётся осью сетки, соседи по ней это соседние ряды в порядке spx, ndx, nikkei, gold, dxy, usdjpy, us3m, us10y, vix, move; это строже, чем соседи только по окну.
- Календарные семейства решают на закрытии бара t о баре t+1 (исполнение по open t+1), то есть позиция держится ровно в выбранный день, месяц или час.
- btc_lead берёт дневное закрытие BTC/USDT (известно в 00:00 UTC следующего дня).
- Набор семейств "all" заморожен списком из 21 семейства этапа 3, чтобы новые семейства не меняли спецификации уже записанных экспериментов.
- Недельный MACD: одна заранее записанная спецификация (без перебора), ETH, только лонг, полная позиция без таргета волатильности; недельные свечи понедельник-воскресенье UTC строятся из дневных, сигнал недели доступен после её закрытия. Месячный MACD не делался: у ETH около 100 месячных свечей, после разгона MACD (35 месяцев) почти не остаётся истории.
- Отчёт сезонности описательный: пробы в журнал не пишет, пишет событие research_seasonality с числом групп. p-значения всех групп отчёта поправлены по Бенджамини-Хохбергу.
- Этап 5 (по запросу пользователя): стратегии против толпы на низколиквидных фьючерсах и бумажный бот. Данные: публичный архив Binance USDT-M (свечи 1h с объёмом рыночных покупок, индекс премии 1h, история фандинга), все символы с USDT, включая снятые с торгов (ошибка выжившего не вносится), с 2020-01; тот же разрез holdout. Открытый интерес и соотношения лонг/шорт в этап не вошли: в архиве они лежат по одному файлу на день и монету (сотни тысяч файлов); ликвидаций в архиве нет.
- Издержки целевой биржи: Hyperliquid, базовая ставка рыночного ордера 0.045% (по сравнениям бирж на 2026 год; перед торговлей сверить). Проскальзывание 0.10% на сторону плюс 0.1 x (сделка / часовой оборот). Фандинг в бэктесте взят с Binance (у Hyperliquid своя история и часовые выплаты); в бумажной торговле платится настоящий фандинг Hyperliquid.
- Значения индекса премии, равные ровно 0 (до 47% часов в 2020 году), считаются пропусками. Сигналы строятся только по фактическим ставкам фандинга; индекс премии используется только для доходности спотовой ноги карри (без него нога считается равной фьючерсу).
- Модель исполнения почасовая: веса решаются на закрытии часа t, держатся час t+1 (open-open). Фандинг, списанный в момент T, относится к часу, который заканчивается в T. Последний час снятой с торгов монеты считается по close. Убыток монеты за час ограничен капиталом под ней. Дрейф весов внутри часа не оплачивается (бумажный бот поэтому торгует монету, только если её вес ушёл от цели больше чем на 2% капитала).
- Вселенная по моменту времени: медиана дневного оборота за 30 прошлых дней (известна в 00:00 UTC дня) от 2 до 100 млн $, монета торгуется не меньше 60 дней, BTC и ETH исключены.
- Сетка: 126 конфигураций в 6 семействах (perps.GRIDS), полный перебор, каждая конфигурация = проба в журнале; соседи для плато: +-1 шаг одного параметра внутри семейства. Перебалансировка семейств по фандингу в 00, 08, 16 UTC сразу после выплаты; каскады проверяются каждый час, не больше 10 позиций по 1/10 капитала.
- Ограничение сделок в месяц (раздел 13) для этапа 5 не применяется: при почасовых барах оно не имеет смысла, издержки учтены полностью, а стресс требует Шарп > 0 при двойных издержках и задержке на 1 и 8 часов. Переносимость на корзину заменена тем, что стратегия сама торгует десятки монет. Синтетика B заменена нулём со сдвигом сигналов.
- Калибровка этапа 5: сигналы каждой монеты (фандинг, признаки каскада) сдвинуты по кругу на случайный сдвиг не меньше 30 дней внутри её истории; цены, вселенная и фактически уплаченный фандинг реальные. FDR = доля путей с находкой. Мощность для этой схемы не оценивается (нет естественного способа подложить сигнал), это отклонение от раздела 11.2.
- Эталоны этапа 5: удержание ETH и ETH с таргетом волатильности на тех же днях (по модели этапа 1). Holdout этапа 5 читается тем же единственным вызовом holdout.load на весь журнал.
- Бумажный бот: только публичные данные, без ключей и ордеров. Сигналы: публичные эндпоинты фьючерсов Binance (те же поля, что в бэктесте), запросы с паузами под лимиты Binance. Исполнение: рыночный ордер идёт по живому стакану Hyperliquid (l2Book), комиссия Hyperliquid; спотовая нога карри по оракульной цене Hyperliquid со спотовой комиссией. Лог paper.sqlite только дописывается; каждый час туда же пишется снимок всех контрактов Hyperliquid (фандинг, открытый интерес, объём) для будущих исследований.
- Проверка в облаке: этап 5 прогнан на 75 из 120 случайно выбранных символов (калибровка 3 пути, поиск, проверки, повтор): движок работает, повтор совпадает с журналом. Это прогон вне рабочего журнала, его числа не являются результатом; полный прогон делает пользователь.
